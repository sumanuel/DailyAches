# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

DailyAches: Expo SDK 58 / React Native 0.88 / React 19 app (plain JavaScript, no TypeScript) for logging people, pain types, pain records, progress and stats. UI copy is in Spanish. It talks to a separate backend, `Dailyaches-api` (not in this repo). Existing docs worth reading before cross-cutting changes: `CONTEXTO_PROYECTO.md`, `ARRANQUE_RAPIDO.md`, `MATRIZ_APP_BACKEND.md`. `roadmap.md` is old aspirational planning, not a source of truth.

## Commands

```bash
npm install
npm run start     # expo start
npm run android
npm run ios
npm run web
npm test                              # Jest (jest-expo preset), tests live in utils/__tests__
npx jest utils/__tests__/gamification.test.js   # a single test file
npm run lint                          # ESLint (eslint-config-expo), currently clean
npx expo-doctor                       # should pass 20/20
```

Tests cover only the pure logic and `httpService` (`gamification`, `apiMappers`, `httpService`); contexts, services and screens are verified manually (smoke test in `ARRANQUE_RAPIDO.md`: register, login, load people/pain-types/records, create each). `npx expo start --web` with `EXPO_PUBLIC_API_URL` pointing at a local `Dailyaches-api` is a quick way to exercise login and the data flow in a browser; `Alert.alert` does nothing on web.

Backend URL: set `EXPO_PUBLIC_API_URL` (the `/api` suffix is appended if missing). Copy `.env.example` to `.env` (git-ignored). Without the variable, `constants/api.js` uses `10.0.2.2:3000` on Android emulators and the Expo host elsewhere (set the variable explicitly on physical devices if the host is a virtual adapter). The production URL is still a placeholder.

## Architecture

- **Entry/providers**: `App.js` nests `ThemeProvider` > `AuthProvider` > `UserProvider` > `PaperProvider` (react-native-paper, themed from `ThemeContext`) > `AppNavigator`.
- **Navigation** (`navigation/AppNavigator.js`): switches between an auth stack and the main app on `isAuthenticated` from `UserContext`. Main app is bottom tabs (Inicio, Registro, Historial, Más), each with its own native stack.
- **State is split in three layers, exposed through one `useUser()` facade**: `context/AuthContext.js` owns only the session (`isAuthenticated`, `authLoading`, login/register/logout) and the 401 handler that logs out on an expired token. `context/UserContext.js` holds the single `user` state (points, level, achievements, profile, people, painTypes, records), persists it to AsyncStorage key `userData:<userId>` (one per account; legacy `userData` is migrated to the first user who logs in), and hydrates it whenever the session changes (remote data when logged in, local data otherwise, reset after logout). `context/useRemoteData.js` is a hook, not a provider: people/pain-type/record API calls and their matching `user` updates, sharing `UserProvider`'s state. Screens keep using `useUser()` for everything. Each list load records `{ loading, loaded, error }` per resource in `remoteStatus` (see `utils/loadStatus.js`); `components/LoadStatusNotice.js` renders the spinner / retry card from it. Record deletes are deferred: `scheduleDeleteRecord` hides the record and calls the API after `DELETE_UNDO_MS` unless `undoDeleteRecord` runs; `components/UndoDeleteSnackbar.js` (mounted in `App.js`) shows the undo prompt. Never remove a record from `user.records` locally without going through the API. Use `utils/confirm.js` (`confirmAction`, `showMessage`) for dialogs: `Alert.alert` does nothing on web. The API deletes a person's records together with the person (migration 002 in `Dailyaches-api`; it must be applied, or the delete fails with a 500), while deleting a pain type that has records answers 409. Create/update/delete actions in `useRemoteData`/`UserContext` return `{ success, error }` (error already in Spanish via `utils/apiErrors.js`); screens must show it instead of closing silently. Changes to API response shapes tend to degrade this silently.
- **Pure logic**: `utils/gamification.js` (levels, achievements, automatic unlock rules, defaults) and `utils/apiMappers.js` (snake_case API payloads to app state, ids converted to strings) have no React or network dependencies.
- **Services** (`utils/*Service.js`) wrap the API per resource (auth, people, painTypes, records) on top of `utils/httpService.js`, a singleton fetch wrapper that returns `{ success, data|error, status }` rather than throwing, injects the Bearer token (in-memory, falling back to AsyncStorage `authToken`), applies a timeout, and calls the handler set by `setUnauthorizedHandler` on a 401 made with a token. Endpoint paths are in `constants/api.js`.
- **API contract**: payloads use snake_case (`image_url`, `whatsapp_enabled`, `person_id`, `pain_type_id`, `pain_level` 1–10); `/records` responses include enriched `person_name`, `pain_type_name`, `pain_type_image`. Renaming any of these breaks at runtime with no compile error. Field-by-field table in `MATRIZ_APP_BACKEND.md`; update it together with `constants/api.js` when the contract changes.
- **UI building blocks**: `components/` (`AppScreen`, `AppTextField`, `HeroPanel`, `IllustrationBadge`) and `constants/illustrations.js`. Forms use react-hook-form + yup.

Export: `utils/exportRecords.js` builds the CSV / PDF HTML (pure) and `utils/exportService.js` writes and shares it (browser download on web, PDF native only).

Daily reminder: `utils/reminders.js` (pure) and `utils/reminderService.js` (expo-notifications, saved per device under `reminderSettings`). Native modules that Expo Go may lack (`expo-notifications`, `expo-file-system`, `expo-sharing`, `expo-print`, `expo-local-authentication`, `expo-secure-store`) are loaded lazily with `require` inside the functions that need them, never imported at the top of a file: a missing module would crash the whole app at start. Reminders need a development build; on web and in Expo Go the switch in Settings is disabled.

Theme colors live in `constants/palettes.js` (light and dark) and are checked by `utils/__tests__/palettes.test.js`: every text/background pair must keep WCAG AA contrast (4.5:1) and the chart bars 3:1 (bar colors are the `chart*` keys, picked in `components/BarCharts.js` by `utils/chartColors.js`: one color per ranking bar, teal to coral by weight for the bars over time). Change a color there, not inline, and run the tests. First-run guide: `screens/OnboardingScreen.js` with steps in `utils/onboarding.js`; `AppNavigator` shows it once per device (AsyncStorage `onboardingSeen`, `utils/onboardingService.js`) before `Main`, and "Más" reopens it. Saving progress (record, achievement, level-up) stamps a transient `user.progressEvent` (`utils/progressEvents.js`, never persisted) that `components/ProgressCelebration.js` shows as a banner. Progress (points, level, achievements) is kept by the API: `ProgressService` and `utils/serverProgress.js` map it into `user`, `UserContext.applyProgress` applies it (`celebrate` stamps the banner event), login syncs it quietly and `createRecordAPI` / `unlockAchievement` use the server's answer. The local rules in `utils/gamification.js` remain only as the fallback when the server does not answer, and the game rules are duplicated in `Dailyaches-api/server/utils/gamification.ts`: change both. Fingerprint login: `utils/biometricService.js` keeps the email and password in `expo-secure-store` with `requireAuthentication` (reading them asks for the fingerprint) and the email alone in AsyncStorage `biometricEmail`; `LoginScreen` shows the "Entrar con huella" button when an account is saved and a "la próxima vez" switch when it is not, Settings can turn it off, and changing the password or deleting the account clears it; a 401 on a fingerprint login clears it too. It is off on web, in builds without the modules and on phones without an enrolled fingerprint. `AppTextField` adds a show/hide eye to any field with `secureTextEntry`. Account security: `AuthService.changePassword` stores the fresh token the API returns, `deleteAccount` (via `AuthContext`/`UserContext`) ends the session and clears the account's local data; a wrong password is a 403, never a 401 (a 401 logs the user out). Screens: `ChangePasswordScreen`, `DeleteAccountScreen`. Lists share two rows: `components/RecordRow.js` (a pain record inside a card: type, intensity, time, notes, and an actions sheet; Home's today log and the per-person history use it) and `components/PersonRow.js` (a person card whose tappable area is separate from `right`, because a button cannot sit inside another one on web; `place` adds a podium medal from `utils/peopleRanking.js`). A person's picture is `components/PersonAvatar.js`: a drawn avatar or a photo. The photo is a 192 px JPEG data URI kept in the same `image_url` field (`utils/avatars.js`, `utils/photoService.js`: expo-image-picker for camera and gallery, expo-image-manipulator to crop and shrink, both loaded lazily), chosen in `AvatarField` through a `BottomSheet`; `SelectField` is the form field that opens a sheet of options. `BottomSheet` uses plain views on web because a button cannot hold buttons there. Shapes tell things apart: pain pictures are circles, people's avatars are rounded squares with a gray frame (`IllustrationBadge`'s `avatar` prop, `avatarBorder` in the palettes). The "more actions" button is `components/ActionMenu.js`, a bottom sheet in a native `Modal` (closes with the Android back button, a tap outside or "Cancelar"); do not use react-native-paper's `Menu` for it: it stayed open and could not be dismissed on a real Android phone. `AppScreen` takes an `overlay` prop for things that must stay fixed over a scrolling screen (the add FAB). Empty lists use `components/EmptyState.js` (illustration, message, optional action). Icon buttons use `components/ActionIcon.js` (44 px target, needs an `accessibilityLabel`).

## UI conventions

`.github/instructions/dailyaches-ui.instructions.md` applies to `screens/`, `components/`, `navigation/` and `ThemeContext`: calm, humane health-app tone; use theme tokens rather than hard-coded colors; rounded soft cards; one primary action per screen; intentional empty states (illustration + short message + CTA); short friendly Spanish copy; consistent card padding/radius.

`.agents/skills/vercel-react-native-skills/` holds installed React Native best-practice rules (list performance, expo-image, native navigators, etc.), pinned in `skills-lock.json`.
